# Pulse operations

Run Pulse in production: the Docker image, its security model, environment variables, toolsets, health routes and CI.

## Deployment artifact

The server ships as a single multi-arch Docker image on the GitHub Container Registry, `ghcr.io/miragon/pulse-server` (`:<version>` or `:latest`):

```bash
docker run --rm -p 127.0.0.1:8400:8400 -e ENGINE_BASE_URL=... -e ENGINE_ID=... \
  ghcr.io/miragon/pulse-server:latest
```

The image keeps the server's `LICENSE` and `THIRD_PARTY_LICENSES.txt` (the works of others its view bundle holds, with their licence files) in `/usr/share/doc/pulse-server`, the licences of its dependencies (the Geist fonts it serves among them) in `/app/node_modules` and Node.js's in `/usr/local/LICENSE`.

SIGTERM stops accepting, lets in-flight requests finish (≤ 4 s; readiness answers them 503 `draining`, so add a Kubernetes `preStop` sleep),
then exits. release-please tags `v<version>`, which `publish-to-docker.yml` pushes after manual approval.
`playground/docker/docker-compose.yml` binds every port to `127.0.0.1` (`--profile full` adds the server); Fly.io: `playground/README.md`.

## Security

Without an OAuth provider the endpoint is unauthenticated and every module without a toolset suffix
runs **read-only**. With one, `/mcp` is an OAuth resource server that verifies each bearer token against the provider's issuer and keys
(401 otherwise, `.well-known` metadata served; it never issues tokens) and the default rises to engine `operations`. The server reads one provider's variables:

| Provider    | Variables                                                                                      |
| ----------- | ---------------------------------------------------------------------------------------------- |
| Keycloak    | `MCP_OAUTH_KEYCLOAK_SERVER_URL` (HTTPS, HTTP on localhost only) and `MCP_OAUTH_KEYCLOAK_REALM` |
| Auth0       | `MCP_OAUTH_AUTH0_DOMAIN`: the tenant domain or its issuer URL                                  |
| WorkOS      | `MCP_OAUTH_WORKOS_SUBDOMAIN`: the AuthKit host                                                 |
| Better Auth | `MCP_OAUTH_BETTER_AUTH_URL`: the auth URL, which is the issuer                                 |
| Convex      | `MCP_OAUTH_CONVEX_AUTH_URL`: the auth URL                                                      |

An incomplete provider, two providers, an invalid value or OAuth without `MCP_URL` fails the boot, naming the variables. A variable it does not read only warns as unknown, so a misspelled provider variable boots **without OAuth**, with every toolset `MCP_ACTIVE_MODULES` names: read the boot log.

<a id="identity-provider-checklist"></a>**Identity provider checklist.** On the provider's side:

| Check   | What to set up                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Token   | Put `<MCP_URL>/mcp` into the access token's `aud` (`https://mcp.example.com/mcp` for `MCP_URL=https://mcp.example.com`: the `resource` that `/.well-known/oauth-protected-resource/mcp` advertises and the boot logs as `OAuth: tokens must carry aud …`; a string, or an array of strings only) and issue `sub`, the caller's identity. `iss` must equal the provider's issuer (Keycloak: `<MCP_OAUTH_KEYCLOAK_SERVER_URL>/realms/<realm>`, so set that variable to Keycloak's frontend URL, which its tokens carry, not an internal address). Any other token gets 401: its `WWW-Authenticate` header names an audience mismatch, and with `MCP_OAUTH_DEBUG=1` the server logs why the signature, issuer, `sub` or `exp` check failed, never the token. Keycloak: an audience mapper (`included.custom.audience`) in a default client scope, plus the `sub` mapper of the built-in `basic` scope, which a realm import that defines its own client scopes has to bring along |
| Clients | Let MCP clients register themselves (Dynamic Client Registration; Keycloak: a Trusted Hosts policy for loopback redirects, which checks every URI a client names, so admit `github.com` for the MCP Inspector and its `client_uri` `https://github.com/modelcontextprotocol/inspector`), or pre-register a client with the redirect URIs `https://claude.ai/api/mcp/auth_callback` (claude.ai, Claude Desktop and mobile) and the loopback ones of local clients such as Claude Code (`http://localhost:<port>/…`, `http://127.0.0.1:<port>/…`, any port). `playground/docker/keycloak/realm-miragon.json` is a working realm with both and the token mappers                                                                                                                                                                                                                                                                                                                  |

A gateway that terminates auth **in front of** the server is invisible to it (identity is only a
bearer token the server validates): such a deployment runs read-only until `MCP_ACTIVE_MODULES`
names its toolsets. A route answers under its own path only, so a path rule in front reads what the server routes on: a request target that is not its own normal form (a dot or empty segment such as `/./mcp`, `/%2e/mcp`, `//mcp` or `/mcp/`, a backslash, a fragment, an absolute URL) gets 404 on every route, ahead of the `Host` check and OAuth; a percent-encoded alias such as `/%6Dcp` matches no route; a `Host` header that is empty, holds more than a host or names none gets 400; a TRACE gets 405 on every path, its `Allow` naming what the route takes (empty where no route holds the path). Deploying a BPMN/DMN is **code execution inside the engine JVM**, so
`engine_create_deployment` also needs `ENGINE_ALLOW_DEPLOYMENTS=true`. Passthrough auth
(`ENGINE_AUTH_TYPE=passthrough`, or a profile's `auth.type`) forwards each caller's token to the engine (under OAuth exactly the token the server verified, and a header with a second credential gets 401),
for a trusted single-audience setup only: the engine could replay it here.

## Environment variables

| Variable                                               | Default                             | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT` / `HOST`                                        | `8400` / `0.0.0.0`                  | HTTP port and bind address of the MCP server (`pnpm dev` binds `127.0.0.1`); `HOST=127.0.0.1` keeps a server behind a proxy in the same host or pod off the network                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `MCP_URL`                                              | unset                               | Public base URL (with OAuth an origin without a path): advertised URLs, the OAuth token audience `<MCP_URL>/mcp` ([checklist](#identity-provider-checklist)), the `Host`/`Origin` the server accepts, and the origin the views load Geist from: the server serves it at `/fonts/geist-<version>/` (woff2, cached immutable, no CDN) and declares it in every bundle view's CSP `resourceDomains`; unset, a view uses the origin its host read it from. A host that blocks the origin, or a gateway that does not route `/fonts/`, shows the host's font                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `MCP_ALLOWED_HOSTS` / `MCP_ALLOWED_ORIGINS`            | localhost-class                     | Further hostnames / origins (comma lists) admitted next to `MCP_URL`'s; any other `Host` (and a POST's `Origin`) gets 403 (DNS-rebinding protection); an origin without a scheme matches any scheme and port, `*` turns the check off (only behind an edge that validates `Host` itself)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `MCP_MAX_BODY_BYTES`                                   | `4194304`                           | Request-body cap (4 MiB): larger bodies get 413 before they are buffered, ahead of the OAuth gate. At most 4× the cap is held across in-flight requests (503 beyond) and a request must arrive within 30 s. An unauthenticated client can still spend that budget, so rate-limit a public server at its proxy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `MCP_OAUTH_*`                                          | unset                               | One OAuth provider's variables, the only caller identity; see [Security](#security)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `MCP_ACTIVE_MODULES`                                   | all, read-only                      | Comma-separated `module` or `module:toolset` entries, e.g. `engine:operations`; no suffix = read-only, under OAuth the standard toolset (see [Module activation](#module-activation)); an unknown module fails the boot, listing the known ones; the boot log's `Toolsets:` line names the modules the list leaves off                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `ENGINES_FILE` / `ENGINES_JSON`                        | unset                               | A profile file as a file path / inline JSON (the file wins), the one format of the CLI, Pulse for VS Code and Pulse for Orca (see [Reference](reference.md#multi-engine)): `{"defaultProfile": "<name>", "profiles": {"<name>": {url, cockpitUrl?, environment?, flavor?, timeout?, readOnly?, auth?}}}`. A profile's name is the engine id; `environment` groups engines in pickers and view heads; `flavor` (`cibseven` \| `operaton` \| `camunda7`, default `camunda7`) selects the cockpit-link routes and product name; `timeout` beats `ENGINE_REQUEST_TIMEOUT_MS`; `readOnly` blocks every write to that engine. A secret is never in the file: `auth.passwordEnv` / `auth.tokenEnv` name the variable, and only `ENGINE_SECRET_*` names are read. A profile the server cannot use (an unknown key, an unset variable, a literal secret, `headers`, a process engine name, OAuth) is refused alone: the boot warns, `engine_list_engines` lists it under `refused`, a call to it fails with `ENGINE_PROFILE_REFUSED`; the boot fails only when the text gives no profile, none is usable or a default names no profile |
| `ENGINE_BASE_URL`                                      | `http://localhost:8410/engine-rest` | Single-engine REST endpoint; with its siblings below the server's one profile (named `ENGINE_ID`); ignored next to `ENGINES_*`, and the boot names each one set. The server warns at boot when no engine source is set at all, naming the fallback URL and id it then uses. Each engine URL (here, a profile's `url`) is the http(s) REST API root: the server never follows a redirect (a 3xx fails the call and says to point the URL at the root, e.g. `https://`; a redirect to a login page means missing credentials), and a 404 of a wrong root fails the call instead of reading as "none"                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ENGINE_ID` / `ENGINE_FLAVOR`                          | `default` / `camunda7`              | Id and vendor (`cibseven` \| `operaton` \| `camunda7`) of the `ENGINE_BASE_URL` shorthand. The id is the per-call `engine` selector and the name the cockpit shows. A CIB seven engine sets `cibseven`, or its links open the Camunda 7 cockpit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `ENGINE_DEFAULT`                                       | unset                               | Where a call without `engine` routes; beats the file's `defaultProfile`. Either must name a profile, or the boot fails; one that names a refused profile warns, and such a call fails with `ENGINE_PROFILE_REFUSED`, never on another engine. Without a default it fails with `ENGINE_NOT_SELECTED` listing the engines (a single profile needs none)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `ENGINE_COCKPIT_URL`                                   | derived                             | `http(s)://` jump-out links to Cockpit; a profile file states `cockpitUrl` per profile instead. | `ENGINE_AUTH_TYPE`                                     | `none`                              | `basic`, `bearer`, `passthrough`, or `none` of the single engine; a profile states its own `auth`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `ENGINE_USERNAME` / `ENGINE_PASSWORD` / `ENGINE_TOKEN` | unset                               | The single engine's credentials, required for `basic` (username + password) / `bearer` (token), else the boot fails. An engine URL (`ENGINE_BASE_URL`, `ENGINE_COCKPIT_URL`, a profile's `url` or `cockpitUrl`) with credentials, a query string or a fragment refuses its profile (with the `ENGINE_*` variables the boot fails), as in the CLI, Pulse for VS Code and Pulse for Orca. A cockpit URL alone may end in the web app's start route (`#/`), which its links drop; a deeper route such as `#/processes` is refused like any other fragment. A login goes into `auth`. No message repeats such a URL or a secret, a boot warning names a variable only in its usual form, and what the model reads names none. Whoever may change the profile file reaches the `ENGINE_SECRET_*` variables and the URLs.
Unknown `ENGINE_*`/`ENGINES_*`/`MCP_*` variables warn at boot, except the `ENGINE_SECRET_*` ones a profile names. The server sends no telemetry.

**Outgoing requests.** The server reaches each engine through `@miragon/pulse-http` over Node's `fetch`: no redirect followed, an answer above 64 MiB fails as too large instead of being read, an empty path value, `.` or `..` is refused before sending, and an integer beyond 2^53 reaches the model as the string of its digits. A write that fails after it may have left says so; a read, a reading POST included, never does.
Behind an outgoing proxy, set `NODE_USE_ENV_PROXY=1` with `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY`. Node 22, 24 and 26 (the image's) honour them; Node 22 and 24 tunnel an `http://` engine through `CONNECT` as well, so such a proxy must allow `CONNECT` to the engine's port. An engine certificate of a private CA needs `NODE_EXTRA_CA_CERTS=<pem file>`, read at start.

## Module activation

`MCP_ACTIVE_MODULES` lists the modules (unset/`all` = every module; one it does not name stays off), e.g. `engine,notes` in
the [starter](build-your-own.md)'s `.env.example`. A module with toolsets runs one per boot:

| Toolset             | Surface                                                                                                                        | No-suffix default |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| `engine:read-only`  | `readOnlyHint` tools only: queries incl. `engine_list_engines`                                                                 | without OAuth     |
| `engine:operations` | + start, claim/assign/complete tasks, variables, job + external-task retries, resolve incidents, messages                      | with OAuth        |
| `engine:admin`      | + delete/modify/suspension, migrations, batch retries, signals, the external-task worker protocol, deployments (with the flag) | never             |

An empty (`engine:`) or unknown suffix warns and falls back to read-only, even under OAuth. A profile with `readOnly` takes no write whatever the toolset (`ENGINE_READ_ONLY`), and the widgets offer none on it.
Widgets hide action buttons whose tool the toolset drops. The full surface is
`engine:admin` plus `ENGINE_ALLOW_DEPLOYMENTS=true`.

## Engine load

The process flow's **Throughput · 30 days** reads the history statistics of the engine (history level `activity` or higher), one query per version that started an instance in the window. On PostgreSQL at 10,000 instances a day a warm read takes about a second and a cold one up to about 15 seconds; an engine whose other processes start far more instances costs more. So the window is fixed, the server keeps a read for an hour per engine, caller and process (per replica), sends one such query at a time per engine and never repeats one by itself: the mode loads when picked, not on Refresh, and a failed read waits for the retry button.

## Observability

Three routes sit next to `/mcp`, outside the OAuth gate and the `Host` check:

| Route           | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/health/live`  | Liveness: 200 as soon as the process serves HTTP                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `/health/ready` | Readiness: 200 while the server serves, 503 `draining` during a drain. Never probes engines: their outages surface as tool errors, not as an unroutable server. `/health` aliases it (Docker `HEALTHCHECK`, Compose, Fly)                                                                                                                                                                                                                                                                                                                                      |
| `/metrics`      | Prometheus text: `mcp_tool_calls_total{tool,outcome}`, `mcp_tool_call_duration_seconds{tool}`, `mcp_http_requests_total{method,route,status}`, `mcp_http_request_duration_seconds{method,route}` plus the standard `process_*`/`nodejs_*` collectors. Labels are bounded by construction (tool catalogue, known routes), never users, sessions or arguments. The tool counters see calls that reached a handler; an unknown tool or invalid arguments show only in the request log. With `MCP_METRICS_TOKEN` set it requires that bearer token (401 otherwise) |

The server logs one line per request to stdout (`tools/call engine_status /mcp 200 client=claude-code/2.1 12ms`: method, tool or resource, path, status, client, time); a failed one ends in `ERROR <text>`.
`MCP_LOG_LEVEL=debug` adds tool arguments and results (cut at 80 characters), `trace` whole requests and responses with credential headers redacted; both log process variables and business keys, and the boot warns.
`/mcp` takes POST only (GET, DELETE and HEAD get 405: the server keeps no session) and `/` serves no page. Node refuses TRACK itself (400) and closes a CONNECT's socket without an answer: neither shows in this log or in `/metrics`. A refused setting fails the boot (exit 1) with one stderr line that names it.

## CI/CD

`.github/workflows/ci.yml` runs on public npm dependencies only: TypeScript (build, test, lint,
format), the CIB seven example, the brand checks, the CLI and the C7 adapter of Pulse for VS Code
and Pulse for Orca against CIB seven and Operaton, the CLI's binaries, image and plugin, the
extension in VS Code and as a .vsix, and the Orca plugin in a pinned Orca release.
A push to `main` runs every job, a pull request those its changes need (`scripts/ci-scopes.mjs`); mutation testing runs nightly.
`docs.yml` checks the docs kit, builds the site on pull requests touching `docs/` (a dead link fails it) and publishes it with each release: `release-please.yml` calls it on `main` after the approval.
