# Pulse operations

Run Pulse in production: the Docker image, its security model, environment variables, toolsets, health routes and CI.

## Deployment artifact

The server ships as a single multi-arch Docker image on the GitHub Container Registry, `ghcr.io/miragon/pulse-server` (`:<version>` or `:latest`):

```bash
docker run --rm -p 127.0.0.1:8400:8400 -e ENGINE_BASE_URL=... -e PROMETHEUS_URL=... \
  ghcr.io/miragon/pulse-server:latest
```

SIGTERM stops accepting, lets in-flight requests finish (≤ 4 s; readiness answers them 503
`draining`, so add a Kubernetes `preStop` sleep), then exits. release-please tags `v<version>`,
which `publish-to-docker.yml` pushes after manual approval. `playground/docker/docker-compose.yml`
binds every port to `127.0.0.1` (`--profile full` adds the server); Fly.io: `playground/README.md`.

## Security

Without an OAuth provider the endpoint is unauthenticated and every module without a toolset suffix
runs **read-only**. With one, `/mcp` validates bearer tokens (401 otherwise, `.well-known` metadata
served) and the default rises to engine `operations`. The server reads one provider's variables:

| Provider    | Variables                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------ |
| Keycloak    | `MCP_USE_OAUTH_KEYCLOAK_SERVER_URL` (HTTPS, HTTP on localhost only) and `MCP_USE_OAUTH_KEYCLOAK_REALM` |
| Auth0       | `MCP_USE_OAUTH_AUTH0_DOMAIN`: the tenant domain or its issuer URL                                      |
| WorkOS      | `MCP_USE_OAUTH_WORKOS_SUBDOMAIN`: the AuthKit host                                                     |
| Better Auth | `MCP_USE_OAUTH_BETTER_AUTH_URL`: the auth URL, which is the issuer                                     |
| Convex      | `MCP_USE_OAUTH_CONVEX_AUTH_URL`: the auth URL                                                          |

An incomplete provider, two providers, a value mcp-use refuses, an unread `MCP_USE_*` variable that
names OAuth or a provider (an `…_AUDIENCE`, a misspelled prefix) or OAuth without `MCP_URL` fails
the boot, naming the variables.

<a id="identity-provider-checklist"></a>**Identity provider checklist.** On the provider's side:

| Check   | What to set up                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Token   | Put `<MCP_URL>/mcp` into the access token's `aud` (`https://mcp.example.com/mcp` for `MCP_URL=https://mcp.example.com`: the `resource` that `/.well-known/oauth-protected-resource/mcp` advertises and the boot logs as `OAuth: tokens must carry aud …`) and issue `sub`, the caller's identity. `iss` must equal the provider's issuer (Keycloak: `<MCP_USE_OAUTH_KEYCLOAK_SERVER_URL>/realms/<realm>`, so set that variable to Keycloak's frontend URL, which its tokens carry, not an internal address). Any other token gets 401: its `WWW-Authenticate` header names an audience mismatch, and with `MCP_USE_OAUTH_DEBUG=1` mcp-use logs a failed signature, issuer, `sub` or `exp` check with the token's claims. Keycloak: an audience mapper (`included.custom.audience`) in a default client scope, plus the `sub` mapper of the built-in `basic` scope, which a realm import that defines its own client scopes has to bring along |
| Clients | Let MCP clients register themselves (Dynamic Client Registration; Keycloak: a Trusted Hosts policy for loopback redirects), or pre-register a client with the redirect URIs `https://claude.ai/api/mcp/auth_callback` (claude.ai, Claude Desktop and mobile) and the loopback ones of local clients such as Claude Code (`http://localhost:<port>/…`, `http://127.0.0.1:<port>/…`, any port). `playground/docker/keycloak/realm-miragon.json` is a working realm with both and the token mappers                                                                                                                                                                                                                                                                                                                                                                                                                                              |

A gateway that terminates auth **in front of** the server is invisible to it (identity is only a
bearer token the server validates): such a deployment runs read-only until `MCP_ACTIVE_MODULES`
names its toolsets. Deploying a BPMN/DMN is **code execution inside the engine JVM**, so
`engine_create_deployment` also needs `ENGINE_ALLOW_DEPLOYMENTS=true`. Passthrough auth
(`ENGINE_AUTH_TYPE=passthrough`) forwards each caller's token to the engine (never to Prometheus),
for a trusted single-audience setup only: the engine could replay it here.

## Environment variables

| Variable                                               | Default                             | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------ | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT` / `HOST`                                        | `8400` / `0.0.0.0`                  | HTTP port and bind address of the MCP server (`pnpm dev` binds `127.0.0.1`); `HOST=127.0.0.1` keeps a server behind a proxy in the same host or pod off the network                                                                                                                                                                                                                                                                                                                                                                                             |
| `MCP_URL`                                              | unset                               | Public base URL (with OAuth an origin without a path): advertised URLs, the OAuth token audience `<MCP_URL>/mcp` ([checklist](#identity-provider-checklist)), the `Host`/`Origin` the server accepts, and the origin the views load Geist from: the server serves it at `/fonts/geist-<version>/` (woff2, cached immutable, no CDN) and declares the origin in every view's CSP `resourceDomains`; unset, a view uses the origin its host read it from. A host that blocks the origin, or a gateway that does not route `/fonts/`, shows the host's font        |
| `MCP_ALLOWED_HOSTS` / `MCP_ALLOWED_ORIGINS`            | localhost-class                     | Further hostnames / origins (comma lists) admitted next to `MCP_URL`'s; any other `Host` (and a POST's `Origin`) gets 403 (DNS-rebinding protection); an origin without a scheme matches any scheme and port, `*` turns the check off (only behind an edge that validates `Host` itself)                                                                                                                                                                                                                                                                        |
| `MCP_MAX_BODY_BYTES`                                   | `4194304`                           | Request-body cap (4 MiB): larger bodies get 413 before they are buffered, ahead of the OAuth gate. At most 4× the cap is held across in-flight requests (503 beyond) and a request must arrive within 30 s. An unauthenticated client can still spend that budget, so rate-limit a public server at its proxy (`pnpm dev` is uncapped)                                                                                                                                                                                                                          |
| `MCP_USE_OAUTH_*`                                      | unset                               | One OAuth provider's variables, the only caller identity; see [Security](#security)                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `MCP_ACTIVE_MODULES`                                   | all, read-only                      | Comma-separated `module` or `module:toolset` entries, e.g. `engine:operations,analytics`; no suffix = read-only, under OAuth the standard toolset (see [Module activation](#module-activation)); an unknown module fails the boot, listing the known ones                                                                                                                                                                                                                                                                                                       |
| `ENGINES_FILE` / `ENGINES_JSON`                        | unset                               | Engine list as a file path / inline JSON (the file wins; highest precedence): `[{id, baseUrl, cockpitUrl?, environment?, flavor?, auth?}, ...]` or the environment map `{"<environment>": [engines…]}`. `environment` groups engines in pickers and view heads; `flavor` (`cibseven` \| `operaton` \| `camunda7`, default `camunda7`) selects the vendor's cockpit-link routes and product name; mixed fleets are fine.                                                                                                                                         |
| `ENGINE_BASE_URL`                                      | `http://localhost:8410/engine-rest` | Single-engine REST endpoint (registered as id `ENGINE_ID`); ignored when `ENGINES_*` is set. The server warns at boot when no engine source is set at all: the silent fallback works against the Compose engine but breaks the `engine_id` join. Each engine URL (here, `baseUrl`) is the http(s) REST API root: the server never follows a redirect (a 3xx fails the call and says to point the URL at the root, e.g. `https://`; a redirect to a login page means missing credentials), and a 404 of a wrong root fails the call instead of reading as "none" |
| `ENGINE_ID` / `ENGINE_FLAVOR`                          | `default` / `camunda7`              | Id and vendor (`cibseven` \| `operaton` \| `camunda7`) of the `ENGINE_BASE_URL` shorthand. The id must match the engine container's `ENGINE_ID` (= the `engine_id` metric label): analytics reads only the configured engine ids, so a mismatch empties ALL analytics for that engine and its health reads `unknown`. A CIB seven engine sets `cibseven`, or its links open the Camunda 7 cockpit                                                                                                                                                               |
| `ENGINE_DEFAULT`                                       | unset                               | Where a call without `engine` routes when several engines are configured. It must name a configured engine id, or the boot fails; without it such a call fails with `ENGINE_NOT_SELECTED` listing the engines (a single engine needs none)                                                                                                                                                                                                                                                                                                                      |
| `ENGINE_COCKPIT_URL`                                   | derived                             | `http(s)://` jump-out links to Cockpit; multi-engine setups use per-engine `cockpitUrl` instead. Unset, links derive from the REST base URL and carry its host. Set a public URL when that host is internal                                                                                                                                                                                                                                                                                                                                                     |
| `ENGINE_AUTH_TYPE`                                     | `none`                              | `basic`, `bearer`, `passthrough`, or `none` (fallback for engines without a per-engine `auth`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ENGINE_USERNAME` / `ENGINE_PASSWORD` / `ENGINE_TOKEN` | unset                               | Required for `basic` (username + password) / `bearer` (token), enforced at boot                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ENGINE_ALLOW_DEPLOYMENTS`                             | `false`                             | `true` registers `engine_create_deployment` (also needs `engine:admin`). Deploying runs code inside the engine JVM. Only `true`/`false` (empty = unset); any other value fails the boot                                                                                                                                                                                                                                                                                                                                                                         |
| `ENGINE_INCIDENT_ISSUE_REPO`                           | unset                               | The one `owner/repo` incident-ticket drafts target with a prefilled GitHub URL (no tool argument redirects it); unset → no URL                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ENGINE_HEALTH_CRITICAL_*`                             | `50` / `25`                         | `…_INCIDENTS` / `…_CLUSTER_SIZE`: open incidents / incidents of one cause from which the live verdict of `engine_status` and the cockpit overview is `critical`                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ENGINE_REQUEST_TIMEOUT_MS` / `PROMETHEUS_TIMEOUT_MS`  | `30000`                             | Per-request deadline (ms) for engine / Prometheus calls: a hung upstream fails the tool call with a timeout error naming it. Whole milliseconds only; anything else fails the boot                                                                                                                                                                                                                                                                                                                                                                              |
| `PROMETHEUS_URL`                                       | `http://localhost:9090`             | Prometheus HTTP API (`http(s)://`), the analytics data source (the repo's Compose stack publishes `:8460`; the server warns at boot when unset). Auth: `PROMETHEUS_BEARER_TOKEN`, or `PROMETHEUS_USERNAME` + `PROMETHEUS_PASSWORD` (URL userinfo moves there); `PROMETHEUS_HEADERS` adds a JSON object of headers (tenant ids). Ambiguous auth fails the boot                                                                                                                                                                                                   |
| `ANALYTICS_ENGINE_IDS`                                 | unset                               | Comma-separated `engine_id`s analytics may read, only for a boot without the engine module; with it active its configured engine ids scope analytics and this is ignored. With neither, every analytics tool refuses (fail-closed), so a shared Prometheus never exposes other teams' engines                                                                                                                                                                                                                                                                   |

Unknown `ENGINE_*`/`ENGINES_*`/`MCP_*` variables warn at boot, a setting renamed from the old module
name fails it ([Upgrading](upgrading.md)); mcp-use telemetry is off (`MCP_USE_ANONYMIZED_TELEMETRY=true` opts in). The engine container takes `METRICS_ENABLED`,
`ENGINE_ID` (must match the server's engine id, or that engine's analytics come back empty),
`OTEL_EXPORTER_OTLP_ENDPOINT`/`OTEL_SERVICE_NAME` and, per node of a clustered engine, `OTEL_RESOURCE_ATTRIBUTES=service.instance.id=<node>`.

## Module activation

`MCP_ACTIVE_MODULES` lists the modules (unset/`all` = every module), e.g. `engine` alone where
no Prometheus exists (the cockpit drops its cross-engine view). A module with toolsets runs one per boot:

| Toolset             | Surface                                                                                                                        | No-suffix default |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ----------------- |
| `engine:read-only`  | `readOnlyHint` tools only: queries incl. `engine_list_engines`                                                                 | without OAuth     |
| `engine:operations` | + start, claim/assign/complete tasks, variables, job + external-task retries, resolve incidents, messages                      | with OAuth        |
| `engine:admin`      | + delete/modify/suspension, migrations, batch retries, signals, the external-task worker protocol, deployments (with the flag) | never             |

An empty (`engine:`) or unknown suffix warns and falls back to read-only, even under OAuth.
Analytics declares no toolsets (every tool is a read): a suffix on it is ignored with a warning.
Widgets hide action buttons whose tool the toolset drops. The full surface is
`engine:admin,analytics` plus `ENGINE_ALLOW_DEPLOYMENTS=true`.

## Observability

Three routes sit next to `/mcp`, outside the OAuth gate and the `Host` check:

| Route           | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/health/live`  | Liveness: 200 as soon as the process serves HTTP                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `/health/ready` | Readiness: 200 while the server serves, 503 `draining` during a drain. Never probes engines or Prometheus: their outages surface as tool errors, not as an unroutable server. `/health` aliases it (Docker `HEALTHCHECK`, Compose, Fly)                                                                                                                                                                                                                                                                                                                        |
| `/metrics`      | Prometheus text: `mcp_tool_calls_total{tool,outcome}`, `mcp_tool_call_duration_seconds{tool}`, `mcp_http_requests_total{method,route,status}`, `mcp_http_request_duration_seconds{method,route}` plus the standard `process_*`/`nodejs_*` collectors. Labels are bounded by construction (tool catalogue, known routes), never users, sessions or arguments. The tool counters see calls that reached a handler; an unknown tool or invalid arguments show only in the request log. With `MCP_METRICS_TOKEN` set it requires that bearer token (401 otherwise) |

mcp-use logs one line per request to stdout (`MCP_USE_LOG_LEVEL=debug`/`trace` adds payloads; the
boot warns). A refused setting fails the boot (exit 1) with one stderr line that names it. Engine
metrics come from the Kotlin plugin via any Micrometer export (see [Architecture](architecture.md)),
Grafana is optional (`:8470`); alert rules ship in `playground/docker/prometheus/alerts.yml`, and
`analytics_engine_health` surfaces the same gauges and firing alerts in one call.

## CI/CD

`.github/workflows/ci.yml` runs on public npm dependencies only: TypeScript (build, test, lint,
format), Kotlin engine plugins, the CIB seven example, the brand checks, the CLI and the VS Code
extension against Camunda 7, CIB seven and Operaton, the CLI's binaries, image and plugin, the extension in VS Code and as a .vsix.
A push to `main` runs every job, a pull request those its changes need (`scripts/ci-scopes.mjs`); mutation testing runs nightly.
`docs.yml` checks the docs kit, builds the site on pull requests touching `docs/` (a dead link fails it) and publishes it from `main`.
