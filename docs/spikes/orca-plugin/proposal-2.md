# Proposal 2: Pulse as an Orca-native cockpit

Spike, 2026-11-07, against Orca 1.4.252. Angle: not "VS Code in Orca", but an engine cockpit that
sits next to coding agents. Feature ids (S, C, P) are those of [the inventory](./inventory.md);
prior-art plugins are those of [prior art](./prior-art.md). Whatever is not backed by a cited doc,
typing or plugin file is marked **guess**.

## Recommendation in short

- **One `trusted-worker` plugin, four surfaces.** The worker owns `.pulse-cli.json`, logins, every
  engine call and the core panels; a components panel in the right sidebar lists engines; an HTML
  custom editor shows the definition, instance and engine views with bpmn-js; a status bar item
  shows open incidents. Frames have no network and get ids and view state only.
- **Full views open as a custom editor on `.pulse-view` handle files** that the worker writes under
  a git-excluded `.orca/pulse/` and opens with `editor.open` (section 3).
- **Read-only first.** v1 = every **must** of the inventory, plus three Orca-only features:
  the status bar glance, "Ask agent about this incident" and "Inspect in a terminal".
- **Writes later, and confirmed outside the frame that asked**: the editor proposes, the
  Orca-drawn sidebar panel confirms, and the worker checks which surface sent the confirmation
  (section 4). No credential ever reaches an agent or a terminal.

## 3. Opening a cockpit tab without a file

| Option                                | For                                                                                                   | Against                                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Custom editor on `.pulse-cli.json`    | no extra file                                                                                         | Orca opens `.json` itself, so the editor is at best an option in the view toggle ([CustomEditorContribution](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-manifest.md#customeditorcontribution); whether `filenames` beats that is a **guess**); one tab per file, no instance tabs; it hijacks a file people edit                        |
| Generated handle file + `editor.open` | worker-initiated from the tree, a command or the status bar; one tab per view; content names the view | needs `workspace:write`; file shows in the tree unless excluded (git-log [openTab](https://github.com/stablyai/orca-community-mirror/blob/36f68b2f304aab6ca9410e90329809d5f20ccd12/src/worker/main.ts#L13-L62), git-control [tab](https://github.com/stablyai/orca-community-mirror/blob/8636505234ddbdf16a82bbabd45c8b5d555c822d/worker/main.mjs#L778-L812)) |
| `newFiles`                            | the + menu entry people know                                                                          | user-started only; lands as `untitled.pulse-view` at the root and, with a template, stays ([prior art 2](./prior-art.md#2-what-newfiles-is))                                                                                                                                                                                                                  |
| Everything in the panel               | no files at all                                                                                       | the right sidebar is narrow, one view at a time, no tabs; bpmn-js needs an HTML panel, not a components one ([prior art 4.1](./prior-art.md#41-navigation))                                                                                                                                                                                                   |

**Recommendation: generated handle files.** The worker writes
`.orca/pulse/<engine>-<view>-<id>.pulse-view` (a stable name per view key, P1), adds `.orca/pulse/`
to `.git/info/exclude`, and calls `editor.open`. The content is
`{ "pulse": 1, "engine": "shop-dev", "view": "instance", "instanceId": "…" }`: names and ids only,
never a URL or a login, so an agent that reads it learns nothing secret. The editor never sees its
path ([custom editors](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md#custom-editors)); it sends the document to the worker in `session.attach`,
which accepts only an engine name it lists itself (orchestra [security](https://github.com/stablyai/orca-community-mirror/blob/a97172382ee0c9eeee0d35de1a7ecf3f297827c0/docs/SECURITY.md)). `newFiles`
"Pulse engine overview" with the template `{ "pulse": 1, "view": "engine" }` is an optional second
launcher.

## 4. Writes without native modals

Pulse's rule stays: an intent from the view carries no authority (`apps/vscode/docs/adr/writes.md`,
"Intents carry no authority"). In Orca it matters more: the editor frame renders engine-controlled
BPMN XML and strings, and Orca has no modal for plugins (frames get `disableDialogs`, [frames](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-isolated-frames.md#isolated-guests-desktop)).

**Route A, the panel confirms (recommended).**

1. The editor sends `writes.propose { intent }`. The core resolves it against its snapshot, as today.
2. The worker keeps a pending write `{ id, fingerprint, target, facts, expiresAt }` in memory for
   60 s, posts `writes.pending` to the engines panel and shows `notifications.show` "Confirm the retry
   in the Pulse panel". Opening the panel from code needs the `orca plugin open` CLI (Orca CLI schema,
   `orca agent-context --json`).
3. The components panel shows a `Callout` with the facts of `apps/vscode/src/host/panels/write-dialog.ts`,
   drawn by Orca from data, so no engine string becomes markup. For `typeHost`
   (`packages/core/runtime-view/src/host-kit/connections/confirmation-policy.ts`) an `Input` takes the host.
4. `writes.confirm { pendingId, typedHost? }` is accepted only when `context.panel.surface` is
   `"panel"` and `contributionId` is the engines panel. Orca hands the worker that caller
   ([PanelCaller](file:///Applications/Orca.app/Contents/Resources/plugins/types/orca-worker.d.ts)); that a frame cannot forge it is a **guess** to verify. The worker re-checks fingerprint, expiry and `WritePolicy`, runs
   `AuditedCommands`, logs, and never retries on its own (beads [send](https://github.com/stablyai/orca-community-mirror/blob/717d9ebb68b04aa802424f3aa2c85eb62f586b19/src/orca/workflow.ts#L254-L285), orchestra [security](https://github.com/stablyai/orca-community-mirror/blob/a97172382ee0c9eeee0d35de1a7ecf3f297827c0/docs/SECURITY.md)).

Trade-off: in VS Code a loopback write needs no confirmation. Here every write would go through the
panel, since the asking surface is the least trusted one. A frame can also call `settings.set`
([methods](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#methods)), so a compromised frame could raise `writes`; the panel step still stands
between it and the engine.

**Route B, the terminal confirms (bulk, migrate, move).** The worker opens a terminal and types
`pulse retry --incident <id> --profile <name>` with `enter: false`; the person's Enter is
the confirmation, and a person typing is never hooked ([terminal.sendText](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#terminalsendtext), [hooks](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#hooks)).
The CLI's guards apply (`--dry-run`, `--yes`, read-only profiles, `docs/cli/safety.md`), and its own
login is used, never the plugin's secrets.

**Agent-driven writes.** An agent never writes through the plugin. It runs the `pulse` CLI in its
own terminal (`docs/cli/agents.md`), behind its harness's permission prompt; the plugin may add the
O7 guard later. A handed-off write is a prompt such as "propose the `pulse retry` command with
`--dry-run` first", never an executed write.

## 5. Frame ↔ worker contract

| `session.intent`                            | `{ intent }` (checked by `MessageGuards.isWebviewIntent`)      | `null`                                                                                  | editor              |
| `session.state`                             | `{ revision? }`                                                | `StateMessage` without `diagramXml`, at most 900 KiB                                    | editor              |
| `diagram.get`                               | `{ definitionId }`                                             | `{ xml }` (cached per id, deployed XML never changes)                                   | editor              |
| `session.attend`                            | `{ visible, active }`                                          | `null`                                                                                  | editor, panel       |
| `agent.ask` / `terminal.inspect`            | `{ incidentId }` / `{ instanceId }`                            | `{ terminalId }`                                                                        | editor              |
| `writes.propose` / `writes.confirm` (later) | `{ intent }` / `{ pendingId, typedHost? }`                     | `{ pendingId }` / `{ done }`                                                            | editor / panel only |

| `PluginPanelEvents`      | Payload                                                | To                       |
| ------------------------ | ------------------------------------------------------ | ------------------------ |
| `session.changed`        | `{ revision, live }` (tens of bytes)                   | one tab, `{ panel: id }` |
| `engines.changed`        | `{}`                                                   | all                      |
| `writes.pending` (later) | `{ pendingId, title, facts, confirmation, expiresAt }` | all                      |
| `worker.ready`           | `{ bootId }`                                           | all                      |

State is pulled, not pushed: a whole state with `diagramXml` could pass the 256 KiB post limit, and
today's publish resends the XML on every tick (`packages/core/runtime-view/src/core/protocol/view-models.ts`). The
sandbox's diagrams are 5 to 12 KB; a state over 900 KiB is answered as a problem state, as
docker-logs caps answers at 900 KiB ([worker](https://github.com/stablyai/orca-community-mirror/blob/64fc3b217c5e1bd67f0b5ce7eb34a3cb16ae68c7/src/worker.ts#L328-L355)). Engine reads run up to 60 s
(`packages/connectors/engine/engine-adapter/src/engine-rest/http/engine-http.ts`), so state requests pass
`timeoutMs: 90000`. A failed write keeps `RuntimeError` in the state; transport failures keep Orca's codes.

## 6. Bundling

- Worker: one esbuild entry with the options of `apps/vscode/scripts/dev-server.mjs` (`platform:
node`, ESM, `node22`, the `createRequire` banner), `orca/*` external, out to `worker/main.mjs`.
  It bundles contract, core, the C7 adapter, engine-core and the pure files of `host/connections`;
  nothing imports `vscode`. Orca's Node is experimental ([stability](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md#stability)); **guess**:
  workers run Electron's Node, 24.22.1 in Orca 1.4.252 (measured with `ELECTRON_RUN_AS_NODE`), so
  `JSON.rawJSON` exists (`packages/connectors/engine/engine-adapter/src/engine-rest/views/lossless-json.ts`).
- Editor frame: the existing build (`packages/core/runtime-view/scripts/webview-build-options.mjs`) unchanged,
  plus a shim script; assets load by relative URL, fonts as files (`font-src 'self'`). The bundle's
  gzip ceiling is 200 KB (`apps/vscode/test/__golden__/bundle-budget.json`), far below the 10 MiB
  entry cap ([files and assets](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md#files-and-assets), [validate](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md#2-load-it-while-you-work)).
- Components panel: build-less `.tsx`, importing only `orca` and relative files, its contract
  types from `protocol.ts` ([hello-worker-panel](https://github.com/stablyai/orca/tree/main/examples/plugins/hello-worker-panel)).
- Placement: apps never import each other (root `CLAUDE.md`). For the spike, an Orca host next to
  `apps/vscode/dev/` inside the same app, with one new allowed entry in
  `apps/vscode/.dependency-cruiser.cjs` (owner decision); later, core, protocol and webview move into
  packages. The build writes a plugin folder like modeler-suite's `plugin/`.

## 7. Live refresh when workers may stop

- A plugin with `main` and status bar items keeps its worker running while enabled
  ([statusBar.update](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#statusbarupdate)), but "workers may be stopped at any time" ([stability](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md#stability)).
  So the worker runs the loops, and nothing that matters lives only in its memory.
- The worker runs one `RefreshLoop` per open tab (`packages/core/runtime-view/src/core/refresh/refresh-loop.ts`) and
  one definitions loop per engine for the status bar, with the cadence, backoff and 401/403 stop as today.
- Each answer carries `bootId`. On `unavailable` or a new `bootId` (also posted as `worker.ready`), a
  tab re-sends `session.attach` with its handle and its saved filters from `localStorage`. Pending
  writes are dropped on purpose.
- Attention comes from the surfaces: tabs send `session.attend` on `visibilitychange`, focus and
  activity, the panel from `ctx.visible`; the worker derives idle after 15 minutes. **Guess**: a hidden
  Orca window fires `visibilitychange` in its guests.
- Orca has no "tab closed" event for the worker (only an in-flight request's `signal` aborts,
  [PanelRequestContext](file:///Applications/Orca.app/Contents/Resources/plugins/types/orca-worker.d.ts)): tabs send `session.detach` on `pagehide`, and the worker drops
  sessions without an attend for three intervals.
- Budget: one `session.changed` per tab per tick; ten local instance tabs at 5 s make 20 posts in
  10 s, well under 200.

## 8. Risks

1. Prompt injection through engine text (O2). Incident messages and business keys are attacker
   reachable. The prompt follows invariant 6: a static intent, ids only when id-shaped, engine text
   fenced as untrusted and capped (600 characters, 8 items, `packages/core/widget-shell/src/ui/ask-ai-prompt.ts`).
   The interface app may not import widget-shell, so the rule needs a copy pinned by a parity test or
   a shared home (owner decision). `packages/core/runtime-view/src/core/views/handover-text.ts` inlines engine text
   unfenced and must not be reused for prompts. Other plugins' `agent.prompt.before` hooks may
   rewrite the prompt ([hooks](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#hooks)).
2. Logins. `secrets` are readable by every surface of the plugin, the bpmn-js frame included
   ([methods](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#methods)). A compromised frame has no network and `openExternal` needs a click and
   asks per host ([frames](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-isolated-frames.md#isolated-guests-desktop)), so exfiltration is hard, not impossible. Agents and terminals
   never get the plugin's logins; for basic-auth engines the CLI needs its own (friction for O3).
3. Worker lifecycle is experimental (Node version, idle stop, channel) ([stability](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-authoring.md#stability)).
4. Handle files need `workspace:write`, appear in the file tree and depend on `.git/info/exclude`
   ([prior art 6](./prior-art.md#6-pitfalls-seen)).
5. Gaps filled by the `orca` CLI (open the panel, focus a terminal, file at a line) tie the plugin
   to CLI flags ([prior art 6](./prior-art.md#6-pitfalls-seen)).
6. Workspaces: `workspace.changed` has no id (name and branch match); SSH and paired workspaces
   are out of reach for Node `fs` in v1.
7. Hooks fail open by default and have 2 s ([hooks](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-host-api.md#hooks)); O7 needs `onError: "deny"` and
   still only binds Claude Code.
8. Components panel limits: no tone per Tree item, 2000 items, no dialog ([limits](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-declarative-ui.md#limits)),
   and it needs the desktop app.
9. Gestures: the panel's confirmation press is not a host-checked gesture; the worker trusts the
   calling surface, not proof that a person pressed ([user gestures](https://github.com/stablyai/orca/blob/main/docs/reference/plugin-declarative-ui.md#user-gestures)).
