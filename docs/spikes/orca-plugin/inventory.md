# Pulse for VS Code: feature inventory for the Orca spike

Merged from three read-only passes over `apps/vscode` (shell and navigation, panels and webview,
connections and trust). One row per user-visible feature. Paths are relative to `apps/vscode/`.
"Node/net" says what the feature needs at runtime: `net` is a call to the engine REST API, `fs` the
workspace file system, `none` nothing beyond the UI.

Priority for a first Orca version: **must** = engine list with incident counts, a definition or
instance view with the bpmn-js diagram and its badges, connecting with credentials kept secret.

## Seams that make the port easier

- **A Node host without VS Code already exists.** `dev/host/dev-host.ts` (317 lines) builds `C7Adapter`,
  `DiagramCache`, `SharedDefinitions`, `EngineLane`, all core panels and `StatePublisher` in plain Node,
  implements `PanelEffects` in about 60 lines, streams state over SSE, takes intents by POST
  (validated by `MessageGuards.isWebviewIntent`) and injects a global `acquireVsCodeApi` shim.
  `apps/vscode/scripts/dev-server.mjs` bundles it with esbuild (`platform: node`, ESM). This is the Orca worker's shape.
- **The webview mounts against any `VsCodeApi`.** `src/webview/main.tsx` calls `acquireVsCodeApi()`;
  `HostBridge` (`src/webview/host/host-bridge.ts`) takes `{ postMessage, getState, setState }` and listens
  to `window` `message` events for `{ type: "state", revision, state, back? }`. A shim script that
  defines `acquireVsCodeApi` before `webview.js` loads is enough; no webview code changes.
- **The webview needs no network.** All data including `diagramXml` arrives in the state
  (`src/core/protocol/view-models.ts`); assets are `dist/webview.js` (IIFE), `dist/webview.css` and
  `dist/fonts/*.woff2`, icons inlined. It reads no `--vscode-*` variable; colours switch on
  `data-cd-theme` alone.
- **The core is host-neutral by rule.** `.dependency-cruiser.cjs` keeps `vscode` and Node built-ins out of
  contract, core, adapters and model. Panels implement `Panel { handle, attend, nudge, dispose }`; every
  host effect goes through `PanelEffects` (`src/core/panels/panel-context.ts`).
- **The read path is vscode-free from the target down.** `TargetsParser` → `CredentialStore` (type-only
  `SecretStorage`) → `EngineLanes` → `EnvironmentClassifier` → `ConnectionBuilder(CompositionRoot.create(),
WriteAudit)` → `C7Adapter(send = fetch)` → `RestEngineClient` → `EngineHttp`. Pure and portable:
  everything in `src/host/connections/` except `connection-registry.ts`, `connection-watcher.ts`,
  `pulse-settings.ts`, `target-discovery.ts`, `targets-file.ts`; plus `src/host/composition-root.ts`,
  `src/host/live/{timer-scheduler,live-wiring}.ts`, `src/host/notification-text.ts`.
- **Tree content is computed in core.** `DefinitionNodes` gives label, description and `withIncident`;
  `Problems.of` gives error texts; `SharedDefinitions` is the cached definitions read.

## Seams that make it harder

- **`ConnectionRegistry` is hard-wired to VS Code** (`vscode.EventEmitter`, `Memento`, static calls to
  `TargetDiscovery.discover()` and `PulseSettings.*`). A worker needs its own small registry.
- **Settings scopes carry trust.** `pulse.writes` and `pulse.liveUpdates` are read from the user scope
  only, so a workspace cannot turn them on (`pulse-settings.ts`). Orca's `contributes.settings` are per
  plugin, not per workspace: that maps to "user scope" and keeps the guarantee.
- **Secret keys include the absolute path** of `.pulse-cli.json` (`credential-store.ts`); the same file
  opened from another path loses its saved login. The origin binding must stay.
- **Many interactions are VS Code modal primitives** (quick picks, input boxes, modal warnings, toasts),
  spread over `src/host/commands` and `src/host/panels/{write-dialog,bulk-dialog,write-confirmation}.ts`.
  The webview README states "a click carries no authority": writes are confirmed outside the webview.
- **Every publish sends the whole state, `diagramXml` included**, on each refresh and live tick.
- **`HostBridge` checks no message origin**; a shim must only forward the plugin's own events.
- **Runtime requirements:** `LosslessJson` needs `JSON.rawJSON` and the reviver's `context.source`;
  engine-core declares `node >=22.22.2`. The worker's Node version must be checked. No proxy or custom CA
  support in `EngineHttp`.
- **Repository rule:** "apps never import each other" (root `CLAUDE.md`). An app at apps/orca may not
  import `apps/vscode/src`. Options: an Orca host inside `apps/vscode` (like `dev/`), extracting core,
  protocol and webview into packages, or an owner decision for the spike.
