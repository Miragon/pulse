# Shop sandbox

A small webshop project for trying Pulse by hand. It has three processes and two
real engines, both with seeded runtime data. Optional live traffic keeps the data moving.
Open this folder in VS Code the way a team would open its process project. Screenshots of
every use case: [docs/screenshots](../docs/screenshots/README.md).

## Start

From the repository root (podman or docker):

```sh
pnpm --filter pulse run sandbox:open      # builds Pulse, starts the engines if needed, opens this folder in VS Code
pnpm --filter pulse run sandbox:up        # (re)creates both engines and seeds them, about 1–2 minutes
pnpm --filter pulse run sandbox:traffic   # optional: live orders on shop-dev until Ctrl+C
pnpm --filter pulse run sandbox:down      # removes both engines
```

`sandbox:open` needs the `code` command on your PATH. It starts its own VS Code instance
with a profile of its own in the temp folder (`pulse-sandbox`), so it never mixes with your
VS Code window; it runs the build from this repository next to your installed extensions. Alternatively, open `apps/vscode` in VS Code and press **F5 → "Run Pulse (sandbox)"**, or
install the VSIX (`pnpm --filter pulse run package`) and open this folder with
`code apps/vscode/sandbox`.

`sandbox:up` always starts from scratch, so run it again to reset all data.

| Process           | File                                             | Deployed on shop-dev                       |
| ----------------- | ------------------------------------------------ | ------------------------------------------ |
| Order fulfillment | `src/main/resources/bpmn/order-fulfillment.bpmn` | v1, v2 and v3 (= this file)                |
| Shipment (called) | `src/main/resources/bpmn/shipment.bpmn`          | v1 only; this file adds an undeployed step |
| Return handling   | `src/main/resources/bpmn/return-handling.bpmn`   | v1 (= this file)                           |

The payment worker's sources are in `src/main/java/io/miragon/shop/payment`, the stock worker's in `src/main/java/io/miragon/shop/stock`. Its stack
traces point at real lines in those files. The shipping worker (Node) is in
`shipping-worker/src`.

The folder recommends the Miragon BPMN modeler (`.vscode/extensions.json`). With it
installed, _Open in model_ shows the diagram and centres the element; without it the file
opens as text at the element's line.

## How the data is made

`apps/vscode/scripts/sandbox` holds everything that is not part of this project: the engine
definitions, the deployed older versions, the scenario catalogue
(`scenarios.mjs`), the order data (`shop-data.mjs`) and the shop's workers
(`workers.mjs`). The seed starts every instance at its start event and walks it along
the path its scenario names (`journeys.mjs`): it completes user tasks, correlates
messages, fires timers and runs the workers until nothing is left, which creates the
failures from the business data, such as an expired card or an overweight parcel. So
every instance has its real history and the History tab shows the whole way.
